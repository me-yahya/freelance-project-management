# Architecture Review

## Big Picture

This is a conventional Rails MVC application.

```text
Browser
  -> config/routes.rb
  -> controller action
  -> model/database queries
  -> ERB view
  -> HTML response
```

There is no React, Vue, Next.js, or separate frontend. Rails renders HTML with
ERB templates.

## Authentication Layer

Generated by Rails:

- `User`
- `Session`
- `Current`
- `Authentication` concern

Login flow:

```text
POST /session
  -> SessionsController#create
  -> User.authenticate_by(...)
  -> create Session row
  -> write signed session_id cookie
```

Every protected request:

```text
request cookie
  -> Authentication concern
  -> find Session
  -> Current.session
  -> current_user
```

## Business Ownership

The app protects user data through associations, not by trusting submitted ids.

Good:

```ruby
current_user.projects.find(params[:id])
```

Risky:

```ruby
Project.find(params[:id])
```

The good version only searches records owned by the logged-in user.

## Main Models

```text
User
Client
Project
Task
Invoice
Session
```

Active Storage adds its own tables for file uploads:

```text
active_storage_blobs
active_storage_attachments
active_storage_variant_records
```

## Controllers

Each resource has a REST-style controller:

```text
ClientsController
ProjectsController
TasksController
InvoicesController
```

The usual REST actions are:

- `index`
- `show`
- `new`
- `create`
- `edit`
- `update`
- `destroy`

Tasks also have:

```ruby
complete
```

because marking a task complete is a specific action on one task.

## Views

Each resource has an ERB folder:

```text
app/views/clients
app/views/projects
app/views/tasks
app/views/invoices
```

Most resources use a `_form.html.erb` partial so the new and edit pages share
one form.

Example:

```erb
<%= render "form", client: @client %>
```

## Database

Migrations describe changes over time. `db/schema.rb` shows the final database
shape.

Foreign keys keep relationships valid:

```text
clients.user_id
projects.client_id
tasks.project_id
invoices.project_id
sessions.user_id
```

Dependent deletes keep orphan records from being left behind:

```ruby
has_many :projects, dependent: :destroy
has_many :tasks, dependent: :destroy
has_many :invoices, dependent: :destroy
```

## Where To Add The Next Feature

Use this checklist for any new resource:

1. Create a migration.
2. Create a model.
3. Add associations.
4. Add validations.
5. Add routes.
6. Add a controller.
7. Add views.
8. Scope all record lookups through `current_user`.
9. Add tests.
10. Run `bin/rails db:migrate` and `bin/rails test`.

That is the basic Rails workflow this app now demonstrates.
